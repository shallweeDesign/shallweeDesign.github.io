CSV 對照表結構與修改方式

這個網站的所有文字與項目都由兩個 CSV 決定。改文案、加套裝、換照片，都不必碰 HTML。 這份說明講清楚兩個檔案各管什麼、彼此怎麼接起來，以及每個欄位實際出現在畫面的哪個位置。

兩種 CSVTwo kinds of file

兩個檔案用途完全不同。搞懂這個區分，剩下的都是細節。

檔案類型一列代表誰會編輯
translations.csv翻譯一個字串你、翻譯
packages.csv結構一個住宿方案你

一句話記住：結構 CSV 決定「有幾個」，翻譯 CSV 決定「寫什麼」。

translations.csv — 所有文字Every string on the site

一列一個字串，四個欄位。目前 114 列。這是唯一需要交給翻譯的檔案。

key,zh-tw,en,ja
nav_booking,線上訂房,Book Now,オンライン予約
packages_title,宿·專案,Stay · Plans,宿泊プラン
欄位說明
key樣板裡 {{nav_booking}} 對應的名字。不要改——改了樣板就找不到，建置會失敗。
zh-tw繁體中文。也是其他語言留空時的備援。
en英文。
ja日文。

內容可以放 HTML

一個 key 可以裝一整塊排版，不只是一句話。kerry_text 整段是兩個 <p>；panel1_content_list 是一整串 <li>。需要換行、分段、清單，直接寫標籤即可。

packages.csv — 有幾個方案How many items exist

一列一個住宿方案。加一列就多一張卡片和一個詳情面板， HTML、JS、CSS 都不用改。欄位放不需要翻譯的東西：識別名稱和圖片。 

card_key,panel_key,panel_id,card_image,card_src,pic_base,pic1_src,pic2_src,pic3_src
pkg1,panel1,pkgPanel1,package-sakura,img/source/package-sakura.jpg,pkg-sakura,…
pkg2,panel2,pkgPanel2,package-zen,img/source/package-zen.jpg,pkg-zen,…
欄位說明
card_key卡片文字的 key 前綴。pkg1 → 樣板去找 pkg1_title、pkg1_desc。
panel_key詳情面板文字的 key 前綴 → panel1_title⋯
panel_id卡片點下去要開哪個面板。
card_image卡片圖產生出來的檔名，不含副檔名。
card_src卡片圖的原圖位置。
pic_base面板三張圖的共同前綴 → 產生 -1 -2 -3。
pic1_src
pic2_src
pic3_src		面板三張圖的原圖位置。

原圖放哪裡

原圖統一放 src/assets/img/source/，欄位就寫 img/source/檔名.jpg。這個資料夾是刻意跟產出目錄 src/assets/img/ 分開的——產圖程式只寫 img/ 的根層， 所以原圖永遠不會被自己的產出蓋掉，重跑幾次結果都一樣。

來源不可以指向這個項目自己的產出檔。那會讀寫同一個檔， 每跑一次就重新壓縮一次。程式啟動時會擋下來並告訴你是哪一個。

兩者怎麼接起來How a row becomes text

樣板裡只寫一份卡片，建置時對 packages.csv 的每一列各產生一份。 文字則靠 key 前綴去翻譯表裡查。

樣板 Template {{t:card_key.title}} 只寫一次
結構 CSV card_key = pkg1 組出 {{pkg1_title}}
翻譯 CSV 櫻花美饌之旅 依語言取對應欄位

第二列 card_key = pkg2 就走同一條路變成「禪風之旅」。有幾列就產生幾張卡片。

欄位出現在哪裡Where each field lands

以下是實際頁面的截圖，虛線框起來的就是那個 key 控制的範圍。 pkgN_ / panelN_ 的 N 代表方案編號—— 第一張卡片是 pkg1_title，第二張是 pkg2_title，依此類推。

標成「替代文字」的 key 在畫面上看不到，它是圖片載入失敗時顯示的文字，也給螢幕閱讀器使用。仍然要翻譯。

常見修改Common edits

只改文字

在 translations.csv 找到那個 key，改對應語言欄，然後 npm run build:i18n。就這樣。

加一個住宿方案

  1. packages.csv 加一列。

    pkg5,panel5,pkgPanel5,package-new,img/source/package-new.jpg,pkg-new,
img/source/pkg-new-1.jpg,img/source/pkg-new-2.jpg,img/source/pkg-new-3.jpg

  2. 四張原圖放到 src/assets/img/source/，檔名要跟上面對得起來。

  3. translations.csv 加這個方案的十四列文字。少一列建置就會失敗。

    — 卡片 —
pkg5_title,pkg5_desc,pkg5_img_alt
— 面板 —
panel5_eyebrow,panel5_label,panel5_title,panel5_tagline
panel5_content_label,panel5_content_list
panel5_notes_label,panel5_notes_text
panel5_img1_alt,panel5_img2_alt,panel5_img3_alt

  4. 產生圖片版本，然後建置。

    npm run img
npm run build:i18n

不用改 HTML、JS 或 SCSS。面板的開關是通用的，第五個面板會自動接上。 唯一要留意的是版面：卡片是兩欄，方案數是奇數時最後一張會單獨佔左半邊。

刪一個方案

packages.csv 刪掉那一列就好。翻譯列留著不影響——建置只查樣板實際用到的 key。

加一個欄位

例如所有方案都要加「適用房型」：樣板區塊加一個 {{t:panel_key.room_type}}，然後每個方案各補一列 panelN_room_type。這是唯一需要動樣板的情況。

注意事項Things that will bite

  • 含逗號的內容要用雙引號包住 key,"甲, 乙",…。用 Excel 或 Numbers 編輯會自動處理；用純文字編輯器要自己顧。
  • 存檔一定要 UTF-8 Excel 若存成 Big5，中文會整片變亂碼。存檔時選「CSV UTF-8」。
  • 三語都要填 留空會退回中文。不會擋下建置，但英日文頁面會出現中文。
  • 不要改 key 欄 那是樣板在用的名字。要改就得同時改樣板，否則建置失敗。
  • 加了項目卻忘了補翻譯，建置會直接失敗 而且會明確列出缺哪幾個 key。這是刻意的——寧可擋下來，也不要讓 {{pkg5_title}} 這種東西上線。 
    ✗ placeholder {{pkg5_title}} has no row in translations.csv
  • Figma 的圖片連結會過期 figma.com/api/mcp/asset/… 是臨時網址，一段時間後全部失效。 原圖一定要實際存進 img/source/，不要只留連結。

指令Commands

指令做什麼
npm run dev開發伺服器，port 3000，中文版預覽。
npm run img產生所有圖片版本（1x／2x、jpg／webp）。加了新圖才需要跑。
npm run build:i18n正式建置，產出 dist/zh-tw/、dist/en/、dist/ja/。
